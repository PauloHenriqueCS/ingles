## Ação prévia necessária para o restante da paridade comportamental

A maior parte dos itens acima com "requer admin real" resolve-se com um único passo manual, fora do escopo desta tarefa (que é só planejamento): **criar um usuário e promovê-lo a `owner` em `admin_users`** no projeto de homologação, depois de o baseline+seed serem aplicados. Isso desbloqueia rodar as funções administrativas (`admin_publish_config_version_v1`, `admin_create_pricing_draft_v1` + `admin_publish_pricing_version_v1`, `admin_publish_gateway_config_v1` etc.) para trazer os estados publicados restantes para paridade com produção, sem inserir diretamente nas tabelas de versão/auditoria.
