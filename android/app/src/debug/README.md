# Debug build environment override

This `debug` source set exists so the **debug** Android build points the
remote-first WebView at **homologation**, while **release** keeps pointing at
**production** — automatically, by build type, with no env var to set and no
file to edit before a build.

## How it works
`android/app/src/main/assets/capacitor.config.json` is generated by
`npx cap sync` from `capacitor.config.ts` and points at production
(`https://app.orodim.com.br`). It is `.gitignore`d (see `android/.gitignore`).

Android Gradle merges assets with **build-type source sets overriding `main`**.
So `src/debug/assets/capacitor.config.json` (this folder) replaces the `main`
one **only for the `debug` variant**:

| Variant | `server.url` used                     | Backend it loads          |
|---------|---------------------------------------|---------------------------|
| debug   | `https://orodim-homolog.vercel.app`   | Supabase homolog + homolog RevenueCat env |
| release | `https://app.orodim.com.br`           | Supabase prod + prod env  |

Supabase project and RevenueCat keys are **not** set natively — they are baked
into whichever web frontend the WebView loads (via each environment's Vercel
`VITE_*` vars), so they follow the host automatically.

## Important
- `npx cap sync` only writes `src/main/assets/…`; it never touches this file,
  so this override is stable across syncs. Keep it tracked in git.
- Keep `server.url` and `server.allowNavigation` in sync (same host) — the
  native `LemonWebViewClient`/`LemonOriginValidator` trust `bridge.getServerUrl()`.
- `applicationId` stays `com.orodim.app` for both variants (not differentiated).
